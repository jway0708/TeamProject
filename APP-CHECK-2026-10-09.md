## Original findings before fixes

1. **Gateway route coverage.** Frontend calls these routes, but `server/index.mjs` does not allow them; the current Android development build will receive 404:
   - Notifications: list, details, mark one read, mark all read.
   - Feedback: list and submission.
   - History: payment, point, assigned stamp, used stamp, redeemed reward, redeemed voucher, spending, voucher-use filters.
   - Top-up details.
   - Account deactivation.
   - Keep-login, device registration, and version checking.
2. **Profile fields removed by the gateway.** The upstream profile has UserId, BirthDate, Image and ImageByte. The gateway returns only Name, PhoneNumber, Email, Tier, Balance, Point, TotalStamp and ReferralCode. Therefore birthday and avatar cannot populate from the upstream profile, and feedback lacks the UserId required by its page.
3. **Empty records shown as errors.** Both real stamp endpoints returned `No Record Found.` with HTTP 200. `records()` treats this as an error. Rewards Mine similarly returns `No Rewards Records Found` and is still treated as an error. Referral empty data has already been handled specifically.
4. **Notification body field mismatch.** Real notifications provide `Content`. List and detail rendering check Description/Message/Address, so they can omit the notification body even after gateway routing is fixed.
5. **Version field mismatch and invisible failure.** Real versions provide OperatingSystem, BuildNumber, VersionCode and Setting. The code looks for AndroidVersionCode; its caught error is stored in updateError, which is not displayed by the current templates.
6. **Release backend address.** `environment.prod.ts` sets nativeApiBaseUrl to an empty string. A production Android app will reject native requests until a deployed backend URL is configured. The development emulator URL is unsuitable for a separately installed phone.
7. **Production OTP login.** Login submission compares the OTP to the entire phone number unconditionally. This rule is appropriate only to the local demo flow; it rejects real SMS OTPs in a production build.
8. **Demo OTP message.** Development Get OTP does not send SMS, but the login, registration and password-reset flows display `SMS sent`. This can mislead someone testing the development build.
9. **Push notifications.** pushEnabled is false. Delivery and Firebase/device setup have not been verified.
10. **Email verification.** The page requests an email OTP but does not implement the final verification step. It currently tells the member to contact support.
11. **Catalogue images.** Homepage accepts only absolute HTTPS Image values. Filename-only images returned by the API are omitted unless the image base URL is established. No URL was guessed during this audit.
